## 1. Constraint that shapes the whole plan

ARKlight cannot embed live charting libraries (no Chart.js/D3/Plotly —
no arbitrary JS/HTML injection is a hard non-goal of the tool, confirmed
directly against `arklight.ir.schema.SCHEMA`). So "data visualization"
has to come from one of two places ARKlight actually supports:

1. **Pre-rendered chart images** (matplotlib → PNG, generated by a
   Python step *outside* ARKlight, dropped in the site's `assets/`
   folder, embedded with `Image`/`Picture`). This is how the pie chart
   and bar charts will be done.
2. **Native zero-JS widgets ARKlight already has schema support for** —
   `Meter`/`Progress` — for simple side-by-side metrics (bundle size,
   satisfaction %). This is a nice built-in demonstration of ARKlight's
   own philosophy (real data viz, zero shipped JS, zero images) sitting
   right next to frameworks that need a runtime to draw anything at all.

Both are planned in, deliberately, so the site itself becomes a working
example of ARKlight's real ceiling — not just a page describing it.

### 2a. Bundle size / shipped JS (gzipped, minimal app)

| Tool | Shipped JS (gzip) | Source |
|---|---|---|
| Svelte 5 | ~1.6–5 KB | State of JS 2025 / multiple 2026 benchmark roundups |

| React 19 + ReactDOM | ~42–48 KB | js-framework-benchmark; multiple 2026 sources (before app code / router / state libs) |
| Angular | ~50–80 KB core, often 1,000+ KB in real apps | 2026 Angular performance roundups |
| **ARKlight — static page (no `State`)** | **0.5 KB** (measured: 919 B raw / 555 B gzip) | **Measured directly, this session** — built `examples`-style page, `gzip -c arklight.js \| wc -c` |
| **ARKlight — page using `State`/`Bind`/`Action`** | **~5.8 KB** (measured: 21.8 KB raw / 5.98 KB gzip) | **Measured directly, this session** — built a counter page with `State("count", 0)` |

Note for the write-up: ARKlight's number for the *static* case isn't a
marketing rounding — pages that declare no `State(...)` literally do
not ship the reactive core at all ("only ship what's used," confirmed
in `CHANGELOG.md`/`PROGRESS.md`). The stateful number already includes
a vendored snabbdom vdom core, which is heavier than the strict minimum
a hand-rolled `textContent` approach would be — worth being honest
about in the copy, not just posting the smallest number.

### 2c. Feature / architecture comparison (qualitative, for a table not a chart)

| Axis | React | Vue | Svelte | Angular | ARKlight |
|---|---|---|---|---|---|
| Output model | Runtime + virtual DOM diffing | Runtime + reactive proxies | Compiles away — vanilla JS, no runtime | Runtime + zone.js/signals | Compiles to static HTML; JS is optional, closed-vocabulary, and only shipped if used |
| Authoring language | JS/JSX | JS/Vue SFC | JS/Svelte SFC | TypeScript | Python |
| Client-side state | Full (hooks) | Full (reactivity system) | Full (runes) | Full (RxJS/signals) | Closed `State`/`Bind`/`Action.*` registry — no arbitrary JS/`eval`, ever |
| Arbitrary custom JS | Yes | Yes | Yes | Yes | **No — permanent non-goal**, not a current limitation |
| Build toolchain required | Yes (bundler) | Yes (bundler) | Yes (compiler) | Yes (CLI/AOT) | No — `pip install`, one CLI, no npm |
| SSR / meta-framework | Next.js | Nuxt | SvelteKit | Angular Universal | N/A — output is already static |
| Responsive styling | `@media`, full CSS | `@media`, full CSS | `@media`, full CSS | `@media`, full CSS | Intrinsic layout only (`.stack`/`.switcher`/`.grid`) — **no `@media` at all today** (v0.048 planned) |
| Ecosystem size | Largest | Large | Small, growing | Large (enterprise) | New — one package, no plugin ecosystem |
| Distribution as single file | No | No | No | No | Yes — `.ark` bundle, sealed by default |

## 3. Site architecture (pages, and which ARKlight primitives build them)

```
/                 Home — headline verdict, KPI strip (Meter widgets), nav
/bundle-size      Bundle Size & Performance — bar-chart image + Meter row
/adoption         Market Share & Sentiment — pie-chart image + SO2025 table
/architecture     How each tool actually works — feature table + pipeline diagram image
/methodology      Sources, and exactly how ARKlight's own numbers were measured
/verdict          Honest "who should/shouldn't use ARKlight" — pulled from
                  ARKlight's own DESIGN-NOTES.md self-assessment
```

Shared: a `nav()` helper (auto `is-active` highlighting, already a built-in
behavior), `Site.style()` for a small custom palette instead of default
utility classes, `.switcher`/`.grid` for the responsive card layouts,
`Details`/`Summary` for an FAQ-style closing section (zero-JS accordion).

Component mapping:
- KPI cards → `Container(class_name="card")` + `Meter`/`Progress` for the visual bar, `Text`/`Heading` for the number.
- Pie chart / bar chart → `Picture`/`Image` pointing at `assets/*.png` generated by a small matplotlib script (not part of the ARKlight package — a one-off asset-generation step, output committed into the site's `assets/` folder like any other image).
- Comparison tables → `Table`/`TableHead`/`TableBody`/`TableRow`/`TableHeaderCell`/`TableCell`.
- Source list → `OrderedList`/`Item` or `DescriptionList` for citation-style entries.
- Page metadata → `Page(..., title=, description=, og_title=, og_image=)` (v0.043 head-metadata props).
